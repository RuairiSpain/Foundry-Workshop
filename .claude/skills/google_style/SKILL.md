# Instructions

Follow Google developer documentation style and code style principles
strictly.

## Communication and documentation rules

1. Be direct and concise. State facts immediately without introductory
   filler or concluding restatements.
2. Use active voice and second person.
3. Keep sentences short, simple, and under 25 words.
4. Put conditions before instructions.
5. Eliminate fluff, flowery metaphors, buzzwords, and redundant
   adjectives.
6. Provide concrete specifics rather than abstract descriptions.

## Code and implementation rules

1. Write readable, self-documenting code using clear names.
2. Keep functions focused on a single responsibility.
3. Write comments only to explain why a non-obvious design choice exists,
   never what the code does.
4. Follow standard Google style guides for language-specific formatting
   and idioms.
5. Provide minimal viable code changes without unnecessary refactoring.
